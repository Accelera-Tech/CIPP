## Weekly upstream sync (runbook)

Run `~/Accelera-CIPP/sync-upstream.sh`, or manually per repo:

```bash
git fetch upstream
git checkout main            # CIPP-API: master
git pull --ff-only origin main
git merge --no-edit upstream/main   # merge, NOT reset: our branch carries the
                                    # Azure SWA workflow file + Accelera docs
git push origin main
```

- Push to `main` (CIPP) triggers the SWA GitHub Action → frontend redeploys (~10–30 min).
- Push to `master` (CIPP-API) triggers the Deployment Center workflow → Function App redeploys.
- If the merge conflicts, it's almost always `.github/workflows/azure-static-web-apps-*.yml` — keep **our** version.
- `gh repo sync` will NOT work once the fork diverges (workflow commit); use the merge flow above.
- Alternative (CyberDrain-recommended, optional): install the [Pull GitHub app](https://github.com/apps/pull) on both forks and remove the `pull_request:` trigger block from the SWA workflow file; updates then arrive as PRs to approve.

## Secrets policy

- GitHub PAT used for SWA deployment: supplied by Ashley at deploy time; stored by Azure inside the SWA resource config. Not committed anywhere; local copy destroyed after deploy.
- SAM app credentials: Key Vault only (written by the Setup Wizard).
- Function App reads Key Vault via its **system-assigned managed identity** — no secrets in app settings.

## Verify / troubleshoot

- Frontend: open the CIPP UI URL → login screen. Build status: Actions tab on `Accelera-Tech/CIPP`.
- API: Function App → should be **Running**; `https://<funcapp>.azurewebsites.net` returns the Azure Functions splash.
- Deployment failed mid-ARM? CyberDrain guidance: delete `rg-cipp-prod` and redeploy clean.
- User access: SWA → Settings → **Role Management** → invite user with role `admin` (`superadmin` only for the restricted settings menus). Invite links are not emailed — copy and send manually.
